# 长文分享（read.历代纪.cn）V0.1 说明

长文分享站与《历代纪》正式作品站完全隔离：QQ 空间只发「摘要 + 阅读全文
链接」，分享站承担完整正文的阅读、长期保存与浏览。

## 一句话工作流

打开 Author Studio → 长文分享 → 新建分享 → 写正文（Markdown，支持粘贴与
复用现有导入能力）→ 保存 → 预览网页 → 准备发布 → 确认 → 网页候选构建并
验证 → 发布任务进入队列 →（启用 QQ 后）到期自动发 QQ 并记录结果。

## 目录结构

- `share-site/` —— 独立 Hugo 站点（自己的 config/layouts/assets，复用正式站
  主题的阅读排版与阅读工具代码，但不引用评论、works 导航或 paragraph-id）。
- `share_publisher/` —— QQ 空间发布器：
  - `db.py`：SQLite 调度数据层（publications 表：web/qzone 双状态机、
    原子认领、幂等键、崩溃恢复；数据库文件位于私有内容根内）。
  - `web.py`：网页发布阶段（构建分享站候选 + manifest 验证）。
  - `qzone.py`：QZone 适配器（NapCat 动态 Cookie、文字说说发布、日志脱敏；
    协议依据见 THIRD_PARTY_NOTICES.md）。
  - `api.py`：Studio 与发布器之间的服务层。
- `scripts/build-share.sh` —— 独立构建：build → candidate → verify →
  不可变 release → `dist/share` 原子切换；产出 manifest.json 与 sha256。
  与正式站 `scripts/build.sh`（→ `dist/site`）互不触发。
- `scripts/preview-share.sh` —— 分享站本地预览（127.0.0.1:1314，含草稿）。
- `deploy/share-systemd/` —— systemd 候选（service + timer，**未启用**）。

## 私有内容根

分享正文绝不出现在公开仓库：

```text
LIDAIJI_SHARE_CONTENT_ROOT   # 环境变量，缺省为仓库上一级 lidaiji-share-private
├── items/<shareId>/index.md # 正文（Markdown 是唯一权威）
└── publications.sqlite3     # 发布调度记录（状态/ID/hash/URL/QQ 结果）
```

- 内容根若落在公开仓库内部会被**拒绝使用**（硬性检查）。
- 分享身份与正式作品完全隔离：`shareId: sh-日期-6位hex`、
  `shareRevision: shareId@sha256(body)[:12]`；保存时自动剥离
  `<!-- paragraph-id:... -->`，绝不生成 articleId。

## 版权防呆

- `excerpt`（摘录）/ `link-only`（仅链接）：分享站页面只显示介绍、摘要、
  来源与原文链接，**绝不渲染完整正文**（模板、RSS、meta 描述均已排除
  正文摘要泄漏；构建契约检查全站扫描验证）。
- `cc`：页面保留来源与许可说明字段。
- 版权模式由作者选择，系统只执行防呆，不自动判断版权。

## 发布与幂等

- 两个发行阶段，独立状态：
  - 网页：`pending → building → verified | failed`
  - QQ：`scheduled → publishing → submitted_unverified → published`
    （或 `failed` / `cancelled` / `skipped`）
- 同一 publication 只执行一次：SQLite `BEGIN IMMEDIATE` + fcntl 文件锁原子
  认领；崩溃残留超过 10 分钟标记 `failed`（stale-claim-recovery），
  **绝不自动重发**，避免重复说说。
- 没有可靠反查前，QQ 提交后只标 `submitted_unverified`（已提交，待反查），
  绝不伪造 `published`。
- 用户可显式为同一篇文章再次新建发布任务（幂等按任务、不按正文）。

## 安全默认

- `QZONE_PUBLISH_ENABLED` 缺省 `false`：绝不向任何 QQ 号真实发送。
- `--dry-run` 只读演练：输出任务、URL、最终文案、长度、revision，
  不发任何网络请求，不出现 Cookie/token。
- 所有日志经脱敏处理；Cookie 每次发布动态获取，不落盘、不进 git。

## 真机验收发现（2026-08-08，测试号 2369520446）

- NapCat v4.18 OneBot11 HTTP 契约：action 写在 URL 路径（`POST /<snake_case_action>`），
  body 直接传参数对象（不包 `{"action":...,"params":...}` 外层）；
  `get_credentials({"domain":"qzone.qq.com"})` 返回 `{cookies, token}`，cookies 含 p_skey/skey。
- 特殊字符（中文/emoji/引号/&/=/?#/换行）在说说中渲染正常；URL 文本完整无损坏。
- 字数实测：471/1186/1594/1747 字符全部完整呈现。
  **V0.1_SAFE_TEXT_LIMIT = 1600**（实测包络 471–1747，保守取 1600；
  API 硬限仍为 2000，UI 预警 1900——均以 Unicode code point 计数）。
- QQ 空间对说说中的外部链接有安全拦截（点击后显示"出于安全考虑，您的访问被拦截"
  页面，用户侧称"501"）。此为 QQ 平台行为，非发布链路缺陷；example.com 测试域被拦截，
  read.历代纪.cn 生产域名的表现需在部署轮实测。
- 测试说说由用户手工清理（无删除 API，不逆向）。
