# V0.3.0 游客段评系统验收报告

日期：2026-07-29  
范围：本地实现、隔离测试、部署准备；未连接或修改正式服务器。

## 实施前审计

- Hugo：0.162.0，定制主题位于 `themes/lidaiji`。
- 正文：Page Bundle 中的 `index.md` 是权威原稿；Word 导入器生成 Markdown。
- 文章永久链接：由栏目目录和显式 slug 组成，标题变化不影响 URL。
- 原项目没有动态 API、评论数据库或管理员认证。
- Nginx 正式 root 为 `/opt/writing-site/current`，与源码和备份隔离。
- 服务器部署文档记录 Node.js 22.12；本地验收使用 Node.js 24.18。

## 架构与身份

- Hugo 继续提供正文、文集、搜索、RSS 和静态页面。
- 独立 Node.js 原生 HTTP 服务只保存段评，使用 Node 内置 SQLite。
- `articleId` 持久写入 Front Matter，不从标题或 URL 推算。
- `paragraphId` 以可迁移的 HTML 注释持久写入 Markdown。
- Word 重导入综合正文、标题上下文、相邻顺序和相似度进行匹配；低置信内容
  使用新 ID 并进入人工检查报告。
- 每次正文变化生成 `articleRevision`。构建后产生最小化
  `comment-manifest.json`，不包含全文。
- 被删除段落的历史评论保留并标记 `orphaned`。

## 数据与安全

SQLite 开启 WAL、外键、busy timeout 和事务，逻辑表包括文章、修订、段落、
评论、审核动作、管理员、会话和限流事件。公共接口只返回 `approved`，不会
返回 IP、来源指纹、审核状态、管理员或内部备注。

管理员密码使用 scrypt；会话 Cookie 使用 HttpOnly、Secure 和
SameSite=Strict；管理写操作使用 CSRF。游客提交还经过同源检查、请求体限制、
纯文本校验、蜜罐、重复检测以及 IP 和匿名浏览器双维度限流。原始 IP 不写入
评论表，只保存使用服务器私密盐生成的 HMAC。

## 发布与回滚

发布顺序为：构建静态站、生成 manifest、备份数据库、迁移并同步评论服务、
健康检查、原子切换静态 release。失败恢复旧静态站、旧评论服务和发布前
数据库。手动回滚同样按对应时间戳一起切换静态站和评论服务，并同步旧
manifest。

评论服务正式目录建议为：

```text
/opt/lidaiji-comments/releases/
/opt/lidaiji-comments/current
/var/lib/lidaiji-comments/comments.sqlite3
/var/backups/lidaiji-comments/
```

## 结论

V0.3.0 已达到本地部署候选状态。正式部署前仍需在服务器创建专用系统用户、
写入 `/etc/lidaiji-comments.env` 的随机 HMAC 密钥、创建站主密码，并在
`nginx -t` 通过后启用同源代理。本轮未执行这些正式服务器操作。
